Read this page first. It is the operating system of this directive, and it deliberately replaces
every schedule with a single rule.
This directive contains no dates, no day counts, no estimates. Sequencing is governed by
exactly one rule:
The moment a step is true, it ships to production — that hour, not that
sprint. Finished and unshipped is a state that does not exist in this
company.
Why every step here is small. Nothing in this document asks you to build an engine. The engines
exist — you built them, and they passed the gate: the extraction pipeline at 91.7% measured
precision, the bi-temporal graph, the nightly synthesis, the receipts plumbing, the chat with cited
sources, the Mind Map live on production. Every step below is a view: a page that reads what the
graph already knows and renders it honestly. A brief is a query plus a layout. A timeline is a query
plus a layout. Intent cards are three queries plus three components. Organized well, each of these is
ordinary front-end work over an extraordinary substrate — and the substrate is done. That is why
this document is confident: the hard part already happened.
THE LAW OF STEPS — CARRIED OVER, WITH ONE NEW RULE
Steps close with a gate: demonstrated on production, verified by the founder, evidence in the
daily doc. No verdict lines from the team — evidence up, verdict back, same day. New for this
directive — the Fan-Out Rule: Steps 0 and 1 are strictly sequential (they establish the shell and
prove the pattern every other surface copies). Once Gate 1 closes, Steps 2, 3, and 4 may run
in parallel across engineers — they are independent views over the same API and share no
code path — provided each still ships individually the moment it is true. Step 5 begins only
after Gates 1–4 are all closed. Sequential where dependencies exist; simultaneous where they
don't. That is how this goes fast without going wrong.

THE SIX
THE ONE EXPERIENCE RULE THAT MAKES V0 FEEL LIKE ONE PRODUCT
Every surface renders the same receipt panel — one shared component: source icon,
timestamp, the exact quoted span highlighted, confidence, validity ("believed since · still
current"). Build it once in Step 0, reuse it everywhere. The receipt-tap is the signature
interaction of the entire company; it must feel identical in the brief, the cards, the timeline, the
feed, and the Mind Map.The API is the only door. No surface queries the graph, the database, or an internal service
directly. If a surface needs something the API can't answer, the API grows first — the surface
never reaches around it.
No receipt, no claim. Every fact on every surface carries its tappable receipt to source + span. A
card that can't cite doesn't render.
Real data only. Every surface builds against and demos on the founder's real account. No mock
data, no seeded fixtures, no placeholder numbers — anywhere, at any stage. If a section is empty
on real data, the empty state renders honestly ("nothing surfaced today") — an honest empty
beats a fabricated full.
Ship-on-true. Merged, deployed, visible on the production URL the hour it passes its gate. The
founder is told the same hour.
Calm over clever. House visual language: warm, quiet, generous whitespace, evidence in
monospace. Cards fade up; nothing pops, nothing spins. No new design systems, no
experiments — consistency with the existing chat and Mind Map.
The deferred list is untouchable. Not in this build, not even a little: the social layer of Signals,
adaptive canvas/tabs, duplex voice, phone runtime, MCP, organs beyond what's live. One hour
spent on any of these is an hour stolen from shipping.EYES — DIRECTIVE 04 · SURFACING CONFIDENTIAL · DO NOT DISTRIBUTE

THE THREE INTENTS (AND ONLY THESE THREE IN V0)
MECHANICS
Intent detection stays simple and honest: match on the query's shape (the API's natural-language
interface already routes these); when an intent matches, the response renders as cards above the
prose answer; when none matches, chat behaves exactly as today. Cards fade up (a standard
motion library is fine — see §09), stagger ~60ms, each ends in the receipt chip →  shared panel. No
canvas, no tabs, no layout re-arrangement — that is the deferred adaptive system; v0 is cards in the
stream.
WHY THIS IS EASY
The queries are the same ones the Brief runs; the cards are the Brief's components reused inside the
chat stream. Step 1 already built most of Step 2.

THE SCOPE — EXACTLY THIS, NOTHING MORE
WHY THIS IS EASY — WITH RECEIPTS
Kokoro-82M is an 82-million-parameter Apache 2.0 model with weights around 327MB that runs fast
even on CPU, with response latency under 2 seconds on a mid-range GPU — reviewers note it beats
models a hundred times its size in blind listening tests. Whisper remains the standard open ASR
pairing for exactly this stack. Nothing here requires a new GPU commitment: CPU-viable TTS +
existing infra + the pipeline you already run. This step is wiring, and the wiring is short. EU
processing rules apply to the audio path exactly as to everything else.
GATE 5
On production: the founder asks one of the three intents aloud, hears the answer spoken,
watches the correct cards render, and taps a receipt. The full loop — voice to proof — in one
breath.A push-to-talk control in the chat: hold →  speak →  release. Speech-to-text via Whisper (the
standard open ASR; a faster-whisper deployment on the existing EU infra, or the browser's
capture streamed to it).
The transcript enters the existing chat pipeline unchanged — same API, same intent cards, same
receipts.
The text answer is spoken back via Kokoro-82M TTS. Cards still render on screen; receipts still
tap. Voice in, voice out, room unchanged.
Not in v0: wake word, duplex, interruption, silence intelligence — the Kyutai presence stack
remains the real voice build, unchanged, on its own track.EYES — DIRECTIVE 04 · SURFACING CONFIDENTIAL · DO NOT DISTRIBUTE
