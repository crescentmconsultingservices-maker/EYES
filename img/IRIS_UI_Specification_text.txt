00How to read this, and the one idea under all of it
The philosophy that makes every later page make sense — and the competitor that proves the
philosophy matters.
Every surface in this document is a window over the Understanding API. None of them holds data;
none of them decides truth. They render what EYES already knows, and they let the user reach the
proof beneath any claim. That single fact is why this is buildable fast: the hard machine is done, and
each surface is an honest rendering of it.
Each surface is specified in two layers, always in this order: the Vision (what it becomes — the full
ambition, so nothing built now points the wrong way) and the v0 Build (what ships first — the smallest
honest version, molecular, with exact parts). Build the v0. Point it at the Vision. Never build something
the Vision would throw away.
WHY THIS EXISTS NOW — THE VENDO SIGNAL
YC's newest batch (S26) just funded Vendo — an open-source agent layer that lets users
compose UI live from a host product's components and API, with a voice mode that renders
views. The interface building itself is now a funded thesis. But read what Vendo is: an agent that
knows the product — its API, its components, its permissions. It has no memory of the person. Its
context resets at every product boundary. Vendo composes what an app contains. IRIS composes
what a life contains — with receipts. They built the customization layer on top of software; we built
the understanding layer beneath all of it. Every design choice in this document should make that
difference visible: a Vendo view is decoration over an app; an IRIS surface is understanding made
legible. We borrow their engineering patterns freely (they are open source) and reject their ceiling
entirely.
Rendering without understanding is decoration. Every surface here renders
understanding — which is the one thing no interface layer above us has.

SPACE, RADIUS, SHADOW, MOTION
THE FIXED SYSTEM
Space scale (px): 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64. Generous whitespace is a feature; when unsure, add space.
Radius: cards 8px · chips/buttons 6px · pills (voice orb, reactions) 999px.
Border: 1px solid #e7e1d4 does the structural work. Borders over shadows.
Shadow (barely there, warm): 0 2px 20px rgba(60,40,20,0.05). Nothing floats hard.

Fraunces (serif) — display, greetings, surface titles, the one emotional beat. Weights 400/500/600/900.
Never for UI labels.
Inter — all body, all UI, all buttons. 400/500/600. The quiet workhorse.
JetBrains Mono — everything that is evidence: timestamps, receipts, data, IDs, kicker labels (uppercase,
letter-spacing 0.15–0.22em). Monospace = "this is provable." This is a signature; honor it everywhere.

02The receipt-depth principle — trust forward, proof
on demand
The most important interaction rule in the app, corrected to its final form. Read carefully; it governs
every surface.
Receipts are not shown by default. The interface does not litter every claim with a citation chip —
that signals anxiety. Instead: the surface stays clean and confident, and the user trusts that any
claim can be opened, because the first time they open one, they learn the whole system works this
way. Proof lives underneath, reachable in layers, as deep as they want to go — but it never shouts.
   A CLAIM ON ANY SURFACE            (clean · no chip · faint affordance only)
        │   hover →  a whisper of underline appears  (proof exists here)
        │   click / zoom →
        ▼
LAYER 1 · the source       which message, which document, when
        │   go deeper →
        ▼
LAYER 2 · the exact span    the precise sentence, highlighted in context
        │   go deeper →
        ▼
LAYER 3 · the full record   the whole email / thread / event, confidence,
                              validity ("believed since · still current"),
                              and every other belief drawn from this source
        │   go deeper →
        ▼
LAYER 4 · the lineage       what this belief superseded, what contradicts it,
                              the chain back through time
ONE CLAIM, FOUR DEPTHS. THE USER CHOOSES HOW FAR TO FALL. DEFAULT VIEW SHOWS NONE OF IT.
THE RULE, STATED FOR PR REVIEW
No surface renders a visible receipt chip in its default state. Every claim is quietly openable: a
hover affordance (faint underline / cursor change) reveals that depth exists; a click opens the
Receipt Panel (§03) at Layer 1, which itself drills deeper. Confidence is carried as trust, not as a
badge. The one exception: the Investigate/Audit surface, where receipts are the product and
appear inline by design (§10). Everywhere else — brief, chat, signals, timeline, dossier — proof is
depth, not decoration.
WHY THIS IS THE RIGHT CALL (AND WHERE IT CAME FROM)
Showing proof everywhere reads as a system defending itself. Holding proof underneath reads as
a system that knows it's right and lets you check. It also keeps every surface calm and beautiful —
the receipts are the foundation, not the furniture. This is the corrected principle; the earlier "chip
on every claim" version is void.

Seven components every surface imports. Building these first (in Step 0) is what makes every later

S1The Receipt Panel THE SIGNATURE · BUILD FIRST
A right-side panel (or centered on mobile) that slides in on any claim-open. Renders the four depths of §02:
source →  span (highlighted) →  full record (confidence + validity) →  lineage. Deep-links from anywhere;
consistent everywhere.
BUILD FROM
shadcn/ui Sheet (MIT) — the slide-in container, right side.
shadcn/ui Tabs — depth navigation (Source / Span / Record / Lineage) if not a scroll.
Motion (framer-motion, MIT) — the slide + the span-highlight fade.
Span highlight: a <mark> with background: var(--accent-soft), animated width.
S2The Understanding Card THE ATOM OF EVERY SURFACE
The base card that renders one unit of understanding — a commitment, a change, a signal, a brief item.
Warm-white, hairline border, fades up on mount. Has a title line, a body line, an optional status chip, and a
quiet claim-affordance (hover underline →  Receipt Panel). Every surface's cards are variants of this one.
BUILD FROM
shadcn/ui Card + Badge (status chip) + Skeleton (loading).
Motion — fade-up 8px, stagger 60ms via a shared variant (define once, import everywhere).
Optional liveliness: Magic UI (MIT, ~21k ★ ) AnimatedList for cards arriving in a stream, NumberTicker for
any count.
S3The Rail + Header THE FRAME
Persistent left rail (~240px): wordmark, nav items with terracotta active-edge, identity block with the ●  live
understanding dot at bottom. Header strip: surface title (Fraunces) + EYES knows · IRIS decides.
BUILD FROM
shadcn/ui Sidebar (official, MIT) — handles collapse, active state, mobile drawer out of the box.
lucide-react (ISC) — icons: Sun (Desk), MessageSquare (Workstation), Rss (Signals), Clock (Timeline), Users

05Surface 1 — The Desk (the Brief)
Not a morning ritual — the company's home screen. The place you sit. State-of-now: what matters
this moment, notifications, today's activity, ambient life. A Mac desktop for a company.
VThe Vision — the desk you sit at WHERE NOTHING IS BUILT WRONG
The Desk is the app's home. Opening IRIS opens the Desk. It is modular and audience-shaped — the
enterprise desk and the consumer desk share bones, show different organs. It holds: the state of now (what
needs doing this moment), notifications living here rather than scattered, today's company activity, a
compact now-strip of the day (a horizontal micro-timeline of today only — distinct from the Timeline
surface), and ambient life — a music control, a mood, whatever makes it a room you want to sit in. It is
glanceable like a desk: you look, you are oriented, you are never "reported to." Widgets are rearrangeable;
the desk is yours.

A responsive widget grid (bento layout). Top-left, largest: the greeting block — Fraunces greeting keyed to
time (Good morning, Abhi.) + one mono line (Tuesday · while you slept, understanding kept moving). The
rest of the grid holds the widgets below, each a variant of the Understanding Card (S2), each fading up in
sequence on load.
THE WIDGETS (EACH AN API QUERY + AN S2 CARD)
ONE EMOTIONAL BEAT
Exactly one Fraunces-italic terracotta line somewhere on the Desk. One. It is the room's heartbeat.
BUILD FROM

shadcn Card variants (S2) for each widget · Motion staggered fade-up.
Magic UI NumberTicker for any count that animates in.

Empty widgets →  S4 honest empty state.

06Surface 2 — The Workstation (the Chat, corrected)
Not "chat with cards." A workstation with two inputs — type or speak — and one intelligence that
knows when you're working and renders the thing itself, not a citation of it. This is where the magic
happens.
VThe Vision — objects obey speech THE INTERACTION GRAMMAR
You type, or you speak. When you speak, you're thinking, and thinking wants visuals — so IRIS renders
artifacts into the room and lets you manipulate them by voice while it talks back. Mention a competitor's
hiring freeze →  the actual article snapshot slides in. Say "put our price chart next to theirs" →  the objects
are placed. Say "connect 2024 and 2025 across X and Y — what do you see?" →  the charts merge and a
simulation runs, live, while you keep talking and it keeps answering. This is not "an app opening inside chat"
(that is trivial and also fine). This is understanding-driven composition: the room assembles from your life
and your words.
THE INTERACTION GRAMMAR — BUILD PRIMITIVES, NOT FEATURES
Every future Workstation capability is a sentence in this grammar. Speaking and rendering happen
simultaneously — voice never blocks the canvas, canvas never blocks voice.
SHOW — pull an artifact (article snapshot, chart, doc, entity) into the room from understanding.
PLACE — arrange artifacts by speech ("put that next to this," "stack these").
MERGE — combine two data objects into one view ("overlay these two years").
SIMULATE — project and render a result ("what happens if this trend holds").
HOLD — pin an artifact so it persists while the conversation moves on.

0The v0 Build — the first words of the grammar HONEST FIRST SENTENCE
THE CONVERSATION STREAM
IRIS replies as un-bubbled flowing prose in --ink on paper — a colleague talking, not a chat bubble. The
user's own lines are small, right-aligned, quieter (--ink-soft, mono-tinted) — the human thinking aloud
shouldn't shout. Prose streams in token by token.
INTENT CARDS (SHOW, V0 SCOPE)
Three intents render structured cards above the prose answer; anything else behaves as normal chat:
Cards fade up staggered. Receipts stay underneath per §02 — no chips; hover reveals depth. Suggestion
chips float above the input so the intents are one tap away (demo-critical).
VOICE CONTROL (V0 = PUSH-TO-TALK; SEE §11)
A push-to-talk orb in the input bar. Hold →  speak →  release →  transcript enters the same pipeline →  cards +
prose render →  answer spoken back. The full grammar (PLACE/MERGE/SIMULATE) is Vision; v0 proves
SHOW + the voice pipe.
BUILD FROM
shadcn/ui base + Vercel AI SDK (useChat, MIT) — streaming prose, token-by-token, out of the box.
Motion — card stagger + prose fade. Magic UI AnimatedList — cards arriving.
Reference Vendo's open-source patterns (github.com/runvendo/vendo, we may borrow): their format-
tagged UI document approach — the agent emits typed blocks the client renders as native components.
Adopt this pattern for intent cards now; it is exactly the substrate the full grammar needs later. Their iframe-
jail sandbox for generated components is the pattern for the future canvas — note it, don't build it yet.
Snapshot-in-room (Vision SHOW of an article): shadcn Card + an <img>/iframe of the source; the article
render is trivial — the understanding deciding to show it is the hard part, and it already exists in the API.
TRUE MEANS
The founder types or speaks the three intents about his real life; correct cards render above streaming
prose; a claim opens to its source underneath; push-to-talk completes the voice → answer loop. The
grammar's first word (SHOW) works; the rest is pointed at, not faked.
"what did I commit to…" →  Commitment cards (S2 variant).
"what's slipping / avoiding" →  Slippage cards, check-in tone.
"what changed about X" →  a before → after Change card (both states claim-openable).

08Surface 4 — The Timeline (the time machine)
Not a bar chart, not a vertical list. A zoomable, scrolling time machine — the company from day
zero, resolving as you dive: quarters →  weeks →  days →  the moment. The magic moment of the
whole product.
VThe Vision — give the company a time machine NO ONE ELSE CAN RENDER THIS
Pull back: the company at altitude, day zero to today. Dive: the view resolves through quarters, weeks, days,
to the moment itself. Every decision node opens into when, why, who, what it triggered, what it superseded
— the receipts, the people, the context, all inside the event. Category rails to travel by theme ("only money,"
"only people," "only product"). Free scrubbing to move through time by hand. As you scroll, the company
happens in front of you — because the bi-temporal substrate kept every past state, and no competitor can
render this, because no competitor stored it. This is understanding made into time travel.

LAYOUT

0Voice v0 — push-to-talk (ships first) ASSEMBLY, NOT RESEARCH
A push-to-talk orb in the Workstation input. Hold →  speak →  Whisper (faster-whisper on existing EU infra)
transcribes →  the transcript enters the existing Workstation pipeline unchanged (same intents, same cards,
same prose) →  the text answer is spoken back via Kokoro-82M. Cards render on screen while it speaks.
Voice in, voice out; the room is unchanged. No wake word, no interruption, no duplex — this is the pipe both
versions share, proven simple first.
BUILD FROM — ALL VERIFIED OPEN-SOURCE, NO NEW COST
Kokoro-82M (Apache 2.0, ~327MB, CPU-viable, sub-2s on mid-GPU) — TTS. Commercial use permitted.
faster-whisper (MIT) — STT on existing EU infra. Browser capture via Web Audio API →  stream to endpoint.
Orb: CSS breathing circle + Motion states (idle/listening/thinking/speaking). Waveform: a light canvas bar-
meter, or wavesurfer.js (BSD) if a richer waveform is wanted.
VVoice Vision — founder-only duplex, tuned on Customer
Zero
AFTER V0 IS
STABLE
Once v0 is stable, stand up Kyutai duplex behind a flag, for exactly one user: the founder. One EU GPU, no
rollout risk, no 32-user exposure. The founder speaks and speaks; every session generates labeled
judgment data — a good-call / bad-call / too-harsh rating on every interruption and silence. What tunes is
not the speech model — it's the judgment layer: the interruption policy, the silence intelligence, the
accountability phrasing, the wait-time after a trail-off. That is the only part of voice the founder's usage
genuinely trains, and it is the part that makes voice IRIS and not a voice mode. By the time voice reaches
alphas, it arrives already tuned to a human. The full grammar (PLACE/MERGE/SIMULATE by voice) lives here
too — voice driving the canvas.
THE ONE FIRM RULE
v0 before duplex, always. The STT → API → cards → TTS pipe is shared by both; proving it simple-first
means the duplex build debugs one new thing (presence), not five.
